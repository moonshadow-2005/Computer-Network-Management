# 元泽瑞：性能管理与计费管理

第 2 组｜网络管理系统项目准备及后续实施职责

你的主要任务是把延迟、吞吐量和接口字节计数转成可解释的性能指标与流量报表。性能和计费共享同一批采样数据，应统一计算口径。方案依据[总体草稿](../开题报告_第2组_10页口播稿.md)。

## (1) 各功能预期完成效果

**性能管理：** 用户能够查看延迟、丢包和接口收发速率趋势，发起指定端点的吞吐量测试，并查看测试参数、状态及结果。

**计费管理：** 用户能够按明确接口或子网边界查询时间段内的入/出流量、查看汇总和数据完整性，并导出报表。初期交付流量统计，可配置单价费用作为扩展。

| 工作 | 你负责交付的内容 |
|---|---|
| 延迟与丢包分析 | 复用金海的 ping 样本，生成趋势与时间段查询结果 |
| 吞吐量测试任务 | 在两台内网主机配对启动 iperf3 服务端/客户端，记录参数、状态、结果和错误 |
| 接口性能计算 | 对字节计数器做有效差分，计算收发速率，条件满足时计算利用率 |
| 流量统计 | 对指定接口或确认的子网边界累计流量增量，按时间筛选与汇总 |
| 报表与导出 | 明确统计方向、单位和数据完整性，生成 CSV 等输出 |
| 模块展示与材料 | 性能与流量页面数据接入、计算说明、验证记录、开题材料 |

本模块首先完成课程明确要求的性能测量和流量统计。模拟单价费用属于可选扩展；接口标称速率、实测吞吐量和采样期间接口负载应分别展示。

### 已验证的环境与立即可做的工作

三台内网测试主机均已验证存在 `/usr/bin/iperf3`，版本为 3.1.3。2026-10-02 从 WSL 复测 `192.168.1.1` 到 `192.168.2.1` 的 2 秒、10 Mbit/s 限速测试，客户端报告接收速率约 9.92 Mbit/s。

```bash
# 在 192.168.2.1 启动一次性服务端
iperf3 -s -1

# 在 192.168.1.1 发起短时限速测试
iperf3 -c 192.168.2.1 -t 2 -b 10M
```

这证明这一方向的功能可用，不能当成链路最大带宽或所有主机对均连通的证据。源地址曾报告为 `192.168.0.1`，需要与金海核对接口、路由和源地址选择，避免错误归属。

你首先整理性能指标和输出字段，再与金海确认计数器读取方式，与蒋天乐确认远程任务、存储与 API 的接入方式。

### 性能管理的具体方法

#### 延迟与丢包

接收金海的 ping 采样，保留目标、时间、RTT（ms）、丢包率（0～100 的百分数）和采集状态。提供时间段查询与曲线；无响应样本与有效 RTT 分开处理，不把无响应填为 0 ms。

#### 端到端吞吐量

用户选择客户端、服务端、测试时长与限速参数后，系统创建任务，确认服务端监听，再启动客户端。记录发送与接收速率、数据量、运行时间和实际测试参数，测试完成或失败后清理本任务启动的服务端。

程序集成拟使用 `iperf3 -J` 输出；先检查 3.1.3 的实际帮助与输出格式，再编写解析。服务端与客户端配合方式见[官方说明](https://software.es.net/iperf/invoking.html)。任务应有超时和同一端点的并发限制，避免冲突；清理时不能终止其他成员的测试进程。

#### 接口速率与利用率

采集 `ifHCInOctets`、`ifHCOutOctets`；可读时使用 `ifHighSpeed`、`sysUpTime`、`ifCounterDiscontinuityTime` 辅助计算。

```text
字节增量 = 本次计数器值 − 上次计数器值
方向速率（bit/s）= 8 × 有效字节增量 / 实际采样时间差（s）
方向利用率（%）= 方向速率 / 参考接口速率（bit/s）× 100
```

首次采样、计数器不连续、设备重启等区间不生成伪造的速率。参考速率未知或为零时不计算利用率。入/出方向分别解释，不把两个方向简单相加作为全双工链路的利用率。[RFC 2863](https://www.rfc-editor.org/rfc/rfc2863)给出了计数器语义与不连续处理要求。

### 计费管理的具体方法

1. 与金海确认哪些接口代表需要统计的链路或子网边界，记录观测点。
2. 对指定窗口中的有效字节增量进行累计，入/出方向分别统计。
3. 实现时间筛选、汇总、CSV 导出，并展示缺失样本或复位等数据质量信息。
4. 用手工算例验证汇总，用受控 iperf3 传输核对计数变化方向与量级。

必须避免把同一流量经过多个设备时的计数全部相加，也不能把采集缺口当成“没有流量”。报表应说明完整性；在无法可靠拆分时，不宣称能够精确统计任意边界时刻。

接口计数器是接口级总量，不能直接给出任意两台主机之间的精确流量。开题时确认接口/链路方向或子网边界统计是否满足验收；若需主机级归属，由组长协调额外流记录或抓包支持。SNMP 流量还可能含协议开销与背景流量，不应要求与 iperf3 应用数据量逐字节一致。

## (3) 组员分工与时间计划

全组分工为：蒋天乐负责总体架构、后端/数据库基础及部署集成；金海负责故障与配置及公共采集；你负责性能测量、流量统计和报表；段景瀚负责安全与公共界面。你负责自己两个模块的算法、任务流程、接口处理、页面数据接入和验证材料。

### 数据交付与协作边界

| 对接人 | 你提供 | 你需要 |
|---|---|---|
| 蒋天乐 | 指标模型、测试任务结果、流量聚合/导出逻辑和接口样例 | 存储与历史查询基础、任务入口、超时/并发机制、API 挂载方式 |

金海维护公共采集访问逻辑，你维护性能与流量算法以及任务流程。你负责本模块的接口处理、查询和页面数据接入，段景瀚提供公共组件。安全模块复用你的指标，不重新采集一套不一致的流量数据。
