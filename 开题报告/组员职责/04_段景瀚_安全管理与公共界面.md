# 段景瀚：安全管理与公共界面组织

第 2 组｜网络管理系统项目准备及后续实施职责

你的主要任务是实现实验网络的风险线索检测与记录，并组织全组共用的页面布局和展示组件。各模块负责人共同完成自己的页面数据接入，你负责界面一致性和公共组件。方案依据[总体草稿](../开题报告_第2组_10页口播稿.md)。

## (1) 各功能预期完成效果

**安全管理：** 用户能够查看服务基线变化、非预期开放端口和持续异常流量的风险记录，追溯目标、时间、规则与证据。数据不足时明确标注为风险线索或待确认结果。

**公共界面：** 五项功能采用一致的导航、筛选、时间、单位和状态展示；各成员能复用表格与图表组件，完成自己的模块页面接入。

| 工作 | 你负责交付的内容 |
|---|---|
| 服务基线 | 已确认目标和允许服务清单；保存检查结果并比较变化 |
| 风险规则 | 新增服务、非预期端口、持续异常流量等规则与证据记录 |
| 安全事件 | 目标、时间、规则、级别、证据与后续状态；去重与变化追踪 |
| 安全页面 | 风险列表、详情、服务变化和规则设置的基本展示 |
| 公共界面 | 导航、布局、设备/时间筛选、表格、状态标签、图表和错误/空数据提示 |
| 联调与材料 | 公共字段使用检查、风险场景验证及全组界面联调记录 |

系统自身的登录功能属于公共应用能力，不能代替实验网络安全风险检测。风险记录应说明证据；服务版本或流量增长不足以直接认定漏洞、攻击类型或攻击源。

## (2) 各功能预期使用方法与工具

| 功能 | 方法与工具 | 数据与使用方式 |
|---|---|---|
| 服务基线与变化 | Python TCP 连接检测，必要时使用 Nmap 连接扫描与服务探测 | 对确认的目标和有限端口记录观测结果，与允许服务基线对比 |
| 异常流量风险 | 复用元泽瑞的性能/流量指标，Python 规则判断 | 对持续阈值或历史基线变化生成带证据的风险记录 |
| 风险存储与查询 | 接入统一后端与 SQLite | 保存事件、样本依据、状态和来源，支持追踪与查询 |
| 公共网页 | HTML/JavaScript/ECharts | 组织布局、表格、图表与提示组件，统一显示各模块 API 的结果 |

### 安全管理的具体任务

1. 与金海确认设备候选清单，建立实际检查的目标和有限端口范围。
2. 设计服务基线对象，记录目标、端口、协议、观测时间、状态和可获得的服务信息。
3. 定期比较基线与当前结果，生成新增服务、非预期端口或其他可解释的变化记录。
4. 复用元泽瑞的流量指标，按持续阈值或历史基线生成异常流量线索。
5. 记录规则触发所依据的样本和时间窗口，并处理重复告警、状态恢复与人工确认。
6. 将风险结果接入蒋天乐的存储与 API，在安全页面展示证据与限制。

初期可用 Python TCP 连接检测。需要服务识别时，可在 DEV 使用 Nmap 的连接扫描和服务探测，见[官方说明](https://nmap.org/book/man-version-detection.html)。检测目标、频率、超时及扫描参数作为可配置项；探测失败应说明原因，不直接宣称端口关闭或目标不存在。

如果老师要求攻击源定位或具体攻击类型判断，需要额外日志、流记录或抓包数据。内部 `test-user` 无 root 权限，不能把在内网主机安装抓包代理或修改系统配置作为已有能力。当前已有数据支持的基础目标是可解释的服务变化和异常流量风险提示。

### 公共界面的具体任务

拟组织总览、设备与拓扑、故障、性能、流量报表、安全风险等页面。总览复用其他成员的结果，呈现采样时间与当前数据状态。

| 你组织的部分 | 各模块负责人承担的部分 |
|---|---|
| 导航、整体布局、公共样式 | 确定自己模块的字段含义、操作和展示需求 |
| 表格、图表、筛选、状态与提示组件 | 提供符合约定的 API 和数据样例 |
| 公共图表单位、时间显示与空值规则 | 接入自己模块的数据，验证展示与后端结果一致 |
| 页面统一检查和公共组件修复 | 修复本模块的业务逻辑、数据与页面接入问题 |

先做公共布局和一个可复用的表格/图表样例，再让各成员接入。可采用 HTML/JavaScript 与 [ECharts](https://echarts.apache.org/en/feature.html)，技术方案与组长统一。

界面应显示未知、超时、尚无有效样本等状态，不把空值画成正常零值；实时数据和示意/回放数据必须能区分。用户触发测试时要能看到任务参数、状态和结果。

## (3) 组员分工与时间计划

全组分工为：蒋天乐负责总体架构、后端/数据库基础及部署集成；金海负责故障与配置及公共采集；元泽瑞负责性能与计费；你负责安全管理与公共界面组织。各模块负责人承担自己的业务逻辑和页面数据接入，你组织公共组件与界面一致性。

### 数据交付与协作边界

| 对接人 | 你提供 | 你需要 |
|---|---|---|
| 蒋天乐 | 安全事件模型、规则配置需求、前端公共字段清单、页面入口 | 风险存储/API 基础、任务调度与部署入口、统一错误和权限安排 |
| 金海 | 服务检查目标/设备属性需求，拓扑与告警展示需求 | 设备/接口标识、逻辑拓扑数据、故障状态、配置变化和查询状态 |
| 元泽瑞 | 风险规则所需指标与时间窗口；图表/报表组件 | 有单位和有效性信息的流量指标、性能曲线数据、统计报表和任务结果 |

建议风险对象包含 `event_id`、`device_id`、观测时间、`rule_id`、类型、级别、证据、状态和数据来源。服务对象包含目标、端口、协议与采样状态；具体字段与组长确认。

你负责安全模块自己的采集/分析、接口处理与页面接入。设备状态和流量来源复用金海、元泽瑞的数据；不自行复制一套 SNMP/ping/流量采集逻辑。数据库结构与 API 公共基础由蒋天乐组织。

### 联调完成标准与验证

- [ ] 已建立目标/服务基线，新增或撤除测试服务时能形成变化记录。
- [ ] 每条风险记录包含目标、时间、触发规则和可核对的证据。
- [ ] 持续异常不会无序产生重复事件，恢复或确认后的状态有记录。
- [ ] 服务探测与流量规则能分别测试；测试/回放数据与实时结果区分。
- [ ] 在 DEV 上创建并撤除临时测试服务，验证服务变化流程及清理结果。
- [ ] 公共表格、图表和状态组件能供其他三人使用，各模块都能接入真实或明确标注的样例数据。
- [ ] 单位、时区、空数据和失败提示一致，界面不会把采样错误误显示为正常状态。
- [ ] 记录当前无法完成的归因与数据限制，不把风险线索写成已确认攻击。

涉及攻击模拟的方式和范围需与老师确认。首轮重点验证服务变化及风险规则，实际攻击源检测应在取得所需证据和实验条件后再扩展。

### 建议时间安排

| 时间 | 你的阶段目标 |
|---|---|
| 第 1～2 周 | 确认获准探测范围、证据字段和公共页面规则；接入后端样本与空值状态 |
| 第 3～4 周 | 建立服务基线/风险记录模型，协调故障、配置、性能页面组件 |
| 第 5～6 周 | 完成安全规则与业务页面接入，复用性能指标并保留风险证据 |
| 第 7～8 周 | 联调五项页面，在 DEV 核对探测失败、去重、恢复及数据来源显示 |
| 第 9 周 | 在获准范围验证临时服务变化或提供标注回放，提交可复现记录与项目报告内容 |

预计项目实施约 9～10 周；最终提交日期尚待老师公布，以上为建议安排。
