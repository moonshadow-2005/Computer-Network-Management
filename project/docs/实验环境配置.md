# 实验环境配置

本地样例只需安装 requirements。以下按第二组实际环境编写：DEV SSH 为 `root@240a:a019::100`，内网地址 `192.168.0.100`，SSH 密码使用课程说明中“第 2 组”的口令。当前实测可读的 SNMP community 是 `public`；是否为课程正式指定凭据仍待确认。

## 先区分访问者与后台运行者

- **访问已有 DEV**：本机建立 SSH 转发，用浏览器访问远程后台；本机无需启动 Python 项目，使用 DEV 服务的管理令牌。
- **自己启动 live**：后台所在机器必须能直接访问实验内网；在该机器配置 `.env` 并运行启动器。只开网页 SSH 转发，不会自动把 SNMP 和 ping 接入内网。
- **已有 systemd 服务**：配置来自 `/etc/nms-team2/nms.env`，由 DEV 维护者修改并重启服务；本机 `.env` 不影响远程服务。

完整分步命令见[项目 README](../README.md)的“真实环境 live：访问与启动”，截图和操作结果见[图文教程](图文使用教程.md)第 12 节。

## 配置入口

在 `project` 目录复制模板：

```bash
test -e .env || cp .env.example .env
```

Windows PowerShell 使用 `if (-not (Test-Path .env)) { Copy-Item .env.example .env }`。编辑 `.env` 后运行 `python run.py --mode live`；已存在的终端环境变量优先。直接运行 `uvicorn app.main:app` 不会自动读取 `.env`，应自行导入环境或使用启动器。

| 变量 | 默认 | 含义 |
|---|---|---|
| `NMS_DB` | `data/nms.sqlite3` | 实验库位置，相对路径由启动器按项目根目录解释 |
| `NMS_API_TOKEN` | 空 | 管理写操作令牌；未配置时写操作不可用 |
| `NMS_ENABLE_LIVE` | `0` | 设为 `1` 允许登记目标的实时采集 |
| `NMS_SNMP_COMMUNITY` | 空 | 本组当前实测使用 `public`；新环境以实际授权配置为准 |
| `NMS_POLL_INTERVAL` | `0` | 秒；大于 0 且 live 开启时执行周期采集 |
| `NMS_ENABLE_SERVICE_PROBE` | `0` | 指定端口 TCP 检查，还需 live 开关、登记目标和已有基线 |
| `NMS_ENABLE_IPERF3` | `0` | 受控 iperf3 任务，还需 live 和服务账户 SSH 条件 |
| `NMS_IPERF_SSH_USER` | `test-user` | 内网测试主机 SSH 用户 |
| `NMS_IPERF_SSH_KEY` | 空 | 运行服务账户可读取的专用私钥路径 |
| `NMS_IPERF_ALLOWED_DEVICES` | 代码默认三台；模板为 host-1,host-2 | 仅允许已配置 SSH 的端点，health 与网页同步限制 |
| `NMS_MAX_ADDRESSES` | `64` | IPv4 地址表最多条数，范围 1～128，达到上限标不完整 |

其他配置：`NMS_SNMP_TIMEOUT=1.5`、`NMS_PING_TIMEOUT=3`、`NMS_MAX_INTERFACES=16`、`NMS_MAX_ROUTES=64`、`NMS_FAULT_THRESHOLD=3`。表读取超过上限会标为部分结果，不把截断内容写成完整新快照。

`.env` 已忽略；管理令牌应设为不可猜测的本机值。可在本机用 Python 的 `secrets.token_urlsafe(32)` 生成并保存，不提交到仓库。

## DEV 与网络条件

课程要求部署到 DEV。SNMP 与内网 ping 采集从能访问课程私有地址的 Linux/WSL/DEV 执行；系统需提供 `ping`。设备候选清单来自作业要求，位于 `app/core/db.py`，变更后应保持 `device_id` 稳定并核对已有数据库。

服务保持单进程和 `127.0.0.1:8000` 监听。从自己电脑访问 DEV，可用 OpenSSH 建立本机转发：

```bash
ssh -N -T -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:18000:127.0.0.1:8000 root@240a:a019::100
```

命令已填好本组账号和入口。保持运行时在本机浏览器打开 `http://127.0.0.1:18000/`，按 `Ctrl+C` 结束转发。本机端口为 18000，远程端口为 8000；原先已有的本机 8000 转发可继续使用。当前电脑通过 Windows WARP SOCKS5 `127.0.0.1:40000` 连接，需沿用已验证的 ProxyCommand 与固定主机密钥；裸命令适用于 IPv6 直通或 SSH 已配置代理的环境，不会自动使用 SOCKS5。

## live 首次采集与结果判断

1. 从访问页面对应的后台取得管理令牌；DEV 的令牌、SSH 密码和 SNMP community 是不同配置。DEV 维护者可登录后用 `sudo less /etc/nms-team2/nms.env` 只读查看，取 `NMS_API_TOKEN=` 后的值（去掉包裹值的引号），普通访问者向维护者取得；本机源码启动则使用自己的 `.env` 中的值。
2. 检查 `/api/v1/health`：database=ok，live_enabled=true；SNMP 采集还需要 snmp_configured=true。poll_interval_s=0 表示手动采集。
3. 填令牌并执行一轮采集，等待结束后查看运行编号与每个目标结果；页面刷新只读已有数据。
4. 再做连续采集，为速率计算提供有效相邻样本。首轮、间隔过长、计数器重置等情况保留无效原因。
5. 选择真实主机与接口，核对记录来源为 live、时间属于本轮。计费窗口使用实际有效样本的时间，不能套用样例的固定日期和 125/250 byte 结果。

WSL 源码放在 `/mnt/c` 时，可以用 `NMS_DB="$HOME/.local/share/nms-team2/live.sqlite3" python3 run.py --mode live --port 8002` 将数据库放在 Linux 文件系统。旧库迁移需要可验证的私有备份权限；不要依靠删除实验库来解决权限问题。

| 现象 | 检查 |
|---|---|
| SSH 无法连接 | 账号、课程入口、IPv6/代理及固定主机密钥配置 |
| 本机端口占用 | 保留已有正确转发，或改本机端口；远程服务端口仍为 8000 |
| 页面可开但采集不可用 | 当前页面是否指向正确后台、live 开关、令牌和服务状态 |
| 已配置却仍显示关闭 | 检查配置属于本机 `.env` 还是 DEV systemd 环境文件，以及终端环境变量优先级 |
| live=true 但 SNMP 失败 | 后台是否真能访问内网、community 和设备响应；SSH 网页转发本身不提供这条采集通路 |
| 速率无效或流量不完整 | 检查采样间隔、有效性和窗口，至少取得连续有效样本 |
| iperf3 失败于 SSH 就绪 | 核对服务账户的用户名、专用密钥、两端授权与 known_hosts；与本机到 DEV 的 SSH 分开处理 |

## iperf3 前置条件

- 两端是已登记、不同的内网测试主机。
- 运行 NMS 的服务账户具备到两端的非交互 SSH 权限，专用私钥与远端授权已获批准。
- 同一个服务账户的 `known_hosts` 已固定并核实两端密钥；程序使用 `BatchMode=yes` 和 `StrictHostKeyChecking=yes`。
- 两端已安装 `iperf3`、`timeout`、`awk`，且可读取 TCP 监听表。
- 开启 live 和 iperf3 后再发起受控任务；API 限制 1～3 秒、最多 10 Mbit/s。

系统按任务启动单次服务端，再启动客户端，并处理超时、取消及清理。工具已预装不代表服务端已常驻启动。

2026-10-17 本组 DEV 已完成 host-1/host-2 的专用受限认证和一次网页真实任务，iperf3 当前开启；host-3 未新增授权。服务 SSH 使用固定主机密钥，关闭 GSSAPI 认证等待并在指定密钥时启用 IdentitiesOnly。新电脑访问已有 DEV 不需要重复配置这两端授权。
