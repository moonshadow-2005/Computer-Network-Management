# 新增探测、诊断与流量归属

更新：2026-10-17。适用于 0.3.0 / SQLite schema v3。

## 1. 启动与已有数据

在 `project` 目录安装依赖后启动本地交互练习：

```bash
NMS_API_TOKEN=local-test-only python3 run.py --mode local --port 8001
```

打开 `http://127.0.0.1:8001/`。新版默认使用 `local-test-v3.sqlite3`，原 v2 样例与其中的确认记录保留在原文件中。真实旧库迁移会先创建并检查私有备份；WSL 推荐将 live 数据库存放在 Linux 用户目录。

真实访问与启动步骤继续见[README](../README.md)和[图文教程](图文使用教程.md)第 12 节。本机源码更新不会自行更新 DEV 服务。

## 2. IP/掩码和拓扑

在“配置管理”查看：

1. **接口 IP 与掩码**：每条记录显示接口、IP、掩码、计算出的子网、采样时间及来源。
2. **地址发现结果**：检查地址表是否完整；unknown/partial 不表示设备没有地址。
3. **逻辑拓扑与快照**：实线为采样子网关系，虚线为课程文档关系；live 为绿色、sample 为紫色。鼠标停在线上可查看依据和时间。
4. **快照比较**：现在能比较 IP/掩码。任一侧未采集地址时显示“未比较”，避免误报删除。

实测关系只说明 IP 与接口属于同一子网，不能据此证明物理直连或把多个入口合并为一台设备。物理身份待进一步核对。

地址表读取依据 [RFC 1213 的 ipAddrTable](https://www.rfc-editor.org/rfc/rfc1213.html#page-31)，默认最多 64 条，可用 `NMS_MAX_ADDRESSES` 调整至 1～128。

## 3. 故障诊断

“故障管理 → 诊断依据与排查建议”跟随设备筛选，展示最近 ping/接口异常的分类、样本依据和建议。超过 5 分钟的样本标为历史；无观测则保持未知。

若主机全部丢包，系统仅关联相近时刻、相同来源、且实测地址属于该主机网段的异常接口。关联线索用于安排排查，不直接确认根因。

## 4. 两种流量统计

### 接口方向总量

原表单继续按接口和时间窗统计。新增观测设备、窗口内已知子网、入/出方向和映射状态。窗口前映射过旧、窗口内地址变化或读取失败时不把整段流量归给单一子网。

### 受控测试的网元对传输量

点击同一个“统计流量”按钮后，下方单独按客户端→服务端显示成功 iperf3 任务的接收字节、任务数及依据；支持 CSV。

本地样例选择 `sample-router:1`，北京时间起止选 `2026-10-13 17:00:00`～`17:00:10`。接口仍为入 125 / 出 250 byte；样例测试网元对为 `sample-host-1 → sample-host-2`，接收 2,300,000 byte。

两个结果测量范围不同，不相加，也不应相互校准。测试汇总只含成功任务，其他业务和协议开销不包含在内；尚未取得全部主机对业务流量的流记录。跨窗口、失败或缺少接收字节的任务不计入。

## 5. 安全规则与边界

- **常见默认 SNMP 读取**：实际成功查询后才生成配置风险线索；证据不保存团体字值。只验证了管理端可读，未测其他网络是否能读。
- **服务基线偏差**：实际开放状态与预期不符时生成风险。
- **潜在 Telnet 管理入口**：已登记且配置基线的 TCP/23 开放时提示核实协议与加密；没有进行协议或漏洞验证。
- **持续高利用率**：连续有效 live 样本满足阈值才生成负载风险，未知和缺口不作为安全证据。

这些规则提供风险依据与处理方向；攻击源定位和完整漏洞扫描仍未实现。实际修改网络 ACL、管理凭据及远端 SSH 授权需按课程环境权限执行。

## 6. 现场验证状态

2026-10-17 已通过现有严格主机密钥 SSH 通路，从 DEV 只读验证 `192.168.0.1` 的地址表：返回 7 条 IP/接口/掩码，sysName 为 FRR-R1。部分实际前缀为 /30，因此课程示意 /24 与实测接口前缀应分别展示。

新版已部署 DEV，schema v3 完整性为 ok。完整采集 run 11/12 读取四个候选的 IP 表分别为 7/7/7/6 条，共 27 条；页面呈现 23 条采样子网关系和单独标记的文档关系。

![实际 DEV 的采样逻辑拓扑](images/tutorial/23-live-observed-topology.png)

### 网页测速

经用户批准，为 DEV 服务账户配置专用私钥；仅向 host-1、host-2 的 test-user 添加限 DEV 来源、禁转发/PTY 的公钥，固定两端主机密钥。host-3 未配置该授权，网页和 API 均限制测试端点。

浏览器实际提交 host-1→host-2、2 秒/10 Mbit/s：任务 succeeded，接收 **2,486,216 byte**，约 **9.94 Mbit/s**。这是限速测试结果，不能推断链路最大容量。

![实际 DEV 网页测速成功](images/tutorial/24-live-iperf-success.png)

### 同一窗口的两种真实统计

北京时间 `2026-10-17 21:55:38`～`21:56:24`，观测接口 r-0-1:3：入 1,006,844、出 3,502,466 byte，覆盖率 100%，子网映射 observed；网元对测试传输统计为上述 2,486,216 byte。接口总量还包含其他业务和管理流量，两个结果不应相等。

![实际 DEV 流量归属和网元对测试统计](images/tutorial/25-live-attributed-accounting.png)

### 真实配置风险

四个候选成功读取后形成默认 SNMP 访问配置风险线索；浏览器已对 r-0-1 的一条记录执行确认，状态 acknowledged。没有改变团体字或制造漏洞，恢复仍待实际配置变化。

换用另一组凭据采集成功不能证明默认凭据已经撤销，系统保留原风险；需另取得有效修复证据。最终实现还会给服务重启中断的采集留下失败记录，防止运行状态永久悬挂。

![实际 DEV 的配置风险与确认状态](images/tutorial/26-live-configuration-risks.png)

### 持续采集与清理

DEV 已启用周期采集，每轮结束等待 15 秒后继续。两轮自动 run 15/16 成功，实际每轮耗时约 25～28 秒，形成有效相邻速率样本。后台在 DEV 运行，浏览器无需常开；点击“刷新数据”读取最新记录。

两端 52000～52999 测试端口范围复查无监听，应用无 pending/running 测速任务，SQLite 完整性 ok。服务探测开关保持关闭，iperf3 仅开放已配置认证的前两台。

## 7. 仍需补充或确认

- 全部网元对的其他业务流量：目前缺少 NetFlow/IPFIX、流日志或等价观测数据；测试传输统计不替代这部分。
- 物理身份与实际直连：当前显示有依据的 IP 子网关系，尚未独立核实物理身份。
- 自然故障恢复、真实配置变化及风险恢复：保留本地逻辑验证和现场边界，不把功能升级产生的新快照当作网络发生变化。
