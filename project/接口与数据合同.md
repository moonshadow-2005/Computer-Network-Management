# 网络管理系统 API 与数据合同

在线 OpenAPI：运行后访问 `/openapi.json`。本文件说明数据库、统一响应与模块间共享字段；API 结构有变化时同步更新本文件和测试。

## 约定总表

| 项目 | 合同 |
|---|---|
| 设备 | `device_id` 稳定唯一；地址不是物理设备身份。课程文件地址先以 `identity_status=candidate` 保存，实测确认后才归并。 |
| 接口 | `interface_id` 为 `<device_id>:<ifIndex>`，`if_index` 只在对应设备内唯一解释。 |
| 路由 | `route_id` 为 `<device_id>:<destination>`；经典路由表可能不能区分同目的的多条路由，后续若真实数据存在此情况须升级标识。 |
| 时间 | 数据库和 API 时间均带 UTC `Z`，格式如 `2026-10-14T01:35:11Z`；浏览器显示本地时区。时间过滤采用起始含、结束不含 `[from,to)`，流量统计的区间结束可以恰好落在 `to`。 |
| 单位 | 累计/差分/汇总为 byte；速率为 bit/s；RTT 为 ms；丢包率、利用率为 0～100 的百分数；接口速率为 bit/s。 |
| 大整数 | 原始 64 位计数和汇总字节量用十进制字符串，前端不要转成 JavaScript `Number` 后再做精确加减。 |
| 不可用 | 无有效数值用 JSON `null`，同时提供 `query_status`、`invalid_reason` 或 `error`。超时/未知不能写成 0、关闭或宕机。 |
| 来源 | 记录中 `data_source` 只说明数据从何而来；`query_status`/`task_state` 才说明执行结果。具体值见下节。 |
| 分页 | 列表支持 `limit`（默认 100，最大 500）和 `offset`（默认 0）；响应有 `total`、`limit`、`offset`。 |
| 权限 | GET 查询无需管理令牌。所有 POST 写操作要求 `X-Admin-Token` 与服务环境变量 `NMS_API_TOKEN` 一致；未配置令牌返回 503，无效令牌返回 401。 |

## 来源与状态

`data_source` 的当前取值：

| 值 | 含义 |
|---|---|
| `document` | 根据课程说明建立的候选清单或逻辑关系；不是实时采样。 |
| `sample` | 构造演示/测试记录；不是实验网结果。 |
| `configured` | 用户通过系统设定的服务基线等配置项。 |
| `live` | 系统在实验目标上实际执行的查询、探测或任务。即使结果为 timeout/failed，来源仍可为 `live`，须再检查查询状态和错误。 |
| `mixed` | 同一结果集合或汇总含多个来源，或入口明确如此标记。 |
| `none` | 状态接口、错误响应或没有样本来源。 |

数据库字段目前不加 CHECK，新增来源前先更新本文件、页面标签和数据样例。采样时间与来源应保持原值。

业务状态值：

- 采集轮次：`running`、`succeeded`、`partial`、`failed`。
- iperf3 任务：`pending`、`running`、`succeeded`、`failed`、`cancelled`。进程重启后遗留的 `pending/running` 任务标为失败，错误码 `INTERRUPTED`，不自动重放。
- 故障事件生命周期：`state=active/recovered`；`acknowledged_at` 独立记录确认时间，可为空。确认告警不会关闭或恢复故障；安全风险继续使用 `open/acknowledged/resolved`。
- 接口状态：已知时为 `up`、`down`、`testing`；查询不到时为 `null`，另看 `query_status`。
- TCP 服务检查：`open` 表示连接成功，`closed` 表示目标明确拒绝连接，`unavailable` 表示无法确认；不可达或超时不能推断关闭。
- 速率区间 `valid=false` 时保留原因，不展示为 0 bit/s。常见 `invalid_reason` 包括首次/前值无效、来源改变、计数器复位/回绕、agent 重启、计数器不连续、采样间隔过长、非递增时间和查询失败。

## 统一 JSON 外壳

成功响应：

```json
{
  "request_id": "b72a7787-2d1f-45d0-b1e6-12f62f4b40af",
  "status": "ok",
  "data_source": "live",
  "generated_at": "2026-10-14T01:35:11Z",
  "data": {
    "items": [],
    "total": 0,
    "limit": 100,
    "offset": 0
  },
  "error": null
}
```

错误响应：

```json
{
  "request_id": "b72a7787-2d1f-45d0-b1e6-12f62f4b40af",
  "status": "error",
  "data_source": "none",
  "generated_at": "2026-10-14T01:35:11Z",
  "data": null,
  "error": {
    "code": "NOT_READY",
    "message": "live collection is disabled",
    "details": {}
  }
}
```

`request_id` 每次响应新建，可用于本地日志关联；不要写入 SNMP community、登录密码或管理令牌。常见错误码为 `UNAUTHORIZED`、`NOT_FOUND`、`CONFLICT`、`INVALID_REQUEST`、`NOT_READY`、`REQUEST_ERROR`。

## API 路径

| 方法 | 路径 | 用途/关键输入 | 写令牌 |
|---|---|---|---|
| GET | `/api/v1/health` | 进程、数据库和功能开关状态 | 否 |
| GET | `/api/v1/overview` | 总量、当前活跃故障/风险、最近采集轮次 | 否 |
| GET | `/api/v1/devices` | 按 `device_id` 查询设备候选 | 否 |
| GET | `/api/v1/interfaces` | 按 `device_id` 查接口状态和采样时间 | 否 |
| GET | `/api/v1/routes` | 按 `device_id` 查最后一次成功完整遍历所得路由；结合每行 `sampled_at` 判断新鲜度 | 否 |
| GET | `/api/v1/topology` | 文档逻辑节点/连接，连接带 `confirmed=false` 与依据 | 否 |
| GET | `/api/v1/config-snapshots` | 按设备、时间、分页查快照 | 否 |
| GET | `/api/v1/config-diff` | 必填查询参数 `before_id`、`after_id`；比较同设备两份快照 | 否 |
| GET | `/api/v1/events` | 按设备、`state`、时间、分页查故障事件 | 否 |
| POST | `/api/v1/events/{event_id}/acknowledge` | 确认故障事件；写入 `acknowledged_at`，不改变 `active/recovered` 状态；重复确认幂等 | 是 |
| GET | `/api/v1/ping-samples` | 查询 RTT、收发包、丢包和查询状态 | 否 |
| GET | `/api/v1/counter-samples` | 查询原始 64 位入/出字节计数与复位元数据 | 否 |
| GET | `/api/v1/interface-status-samples` | 查询接口状态历史 | 否 |
| GET | `/api/v1/metrics` | 查询接口速率/利用率及有效性；当前唯一 `kind` 为 `interface_rate` | 否 |
| GET | `/api/v1/traffic` | 必填 `interface_id`、`from`、`to`；`direction=in/out/both` | 否 |
| GET | `/api/v1/traffic/export.csv` | 与流量 API 相同窗口和方向的 CSV | 否 |
| GET | `/api/v1/service-baselines` | 查询已配置端口基线 | 否 |
| POST | `/api/v1/service-baselines` | 保存 `device_id`、端口、是否允许和说明 | 是 |
| GET | `/api/v1/service-checks` | 查询端口检查结果 | 否 |
| POST | `/api/v1/security/probe` | 对已登记目标、已配置基线的单个端口做 TCP 连接检查；须同时启用 live 和 probe | 是 |
| GET | `/api/v1/risks` | 按设备、状态、时间、分页查询安全风险 | 否 |
| POST | `/api/v1/risks/{risk_id}/acknowledge` | 确认风险 | 是 |
| GET | `/api/v1/tasks` | 查最近任务及状态 | 否 |
| GET | `/api/v1/tasks/{task_id}` | 查单个任务 | 否 |
| POST | `/api/v1/tasks/iperf3` | 创建限时、限速、受端点互斥约束的测试 | 是 |
| POST | `/api/v1/tasks/{task_id}/cancel` | 请求取消任务 | 是 |
| GET | `/api/v1/collector-runs` | 查询采集轮次及逐设备结果 | 否 |
| POST | `/api/v1/collect` | 手动执行一次或指定设备采集；须启用 live | 是 |

时间过滤必须同时提供 `from` 和 `to`，值为带时区 ISO 8601；`from < to`。列表 API 以 `[from,to)` 过滤时间字段。监听和写操作配置见[实验环境配置](docs/实验环境配置.md)；服务以单进程启动。

## 核心记录样例

```json
{
  "device_id": "r-0-1",
  "interface_id": "r-0-1:2",
  "if_index": 2,
  "description": "ens3",
  "admin_status": "up",
  "oper_status": "up",
  "reference_speed_bps": null,
  "query_status": "ok",
  "sampled_at": "2026-10-14T01:35:11Z",
  "data_source": "live"
}
```

一个计数器样本另含 `in_octets`、`out_octets`、`sys_uptime_ticks`、`discontinuity_ticks`；这些整数以十进制字符串储存。相邻样本有效时，速率 `8 × byte_delta / 实际秒数`。参考速率缺失、为零或不可靠时利用率是 `null`。

流量报表包含 `interface_id`、观测点、窗口、方向、`in_bytes`/`out_bytes`、`coverage_pct`、`complete`、无效区间 ID/原因和 `data_source`。`source_sample_ids` 是参与有效区间计算的原始 `counter_samples.sample_id`，按时间顺序去重；`metric_sample_ids` 是参与汇总的派生 `metric_samples.metric_id`。字节是只累计窗口内完整有效的采样区间，边界不外推；`complete=true` 要求从窗口起点到终点连续覆盖且无无效区间。CSV 与 JSON 使用同一统计结果，字节列保留十进制字符串。

配置快照的 `content` 以接口 ID 和路由 ID 为键保存规范化字段。只有表完整遍历后才写入可对比快照；路由 API 保留上次成功完整结果，采集失败时不伪装成空路由。由于接口表 API 当前直接展示最后采样状态，必须查看 `sampled_at` 与 `query_status` 判断它是否新鲜。

## SQLite 版本与迁移

数据库版本使用 `PRAGMA user_version`。当前 `CURRENT_SCHEMA_VERSION=2`。给已有库升级前，通过 SQLite Online Backup API 在数据库同级 `backups/` 目录生成 `*.pre-v{旧版本}-to-v2-*.sqlite3` 副本，权限设为并验证为 `0600`；若文件系统不能落实私有权限，则删除该备份并拒绝迁移。新空库不额外备份。v0→v1 为旧版 `service_baselines` 增加 `data_source TEXT NOT NULL DEFAULT 'configured'`；v1→v2 为 `events` 增加可空的 `acknowledged_at`。两次迁移都保留已有数据，重复启动幂等；迁移完成才提交版本号。遇到更高版本直接拒绝启动，不降级、不覆盖。备份目录在 `data/` 下，由 Git 忽略。WSL 的 `/mnt/c` 若以宽松模式挂载，旧库迁移应先移至支持 Unix 权限的私有 Linux 文件系统。

迁移前应先停止服务并保留备份。恢复时不要覆盖运行中的数据库：将备份用 SQLite Online Backup API 恢复为新文件，检查 `PRAGMA integrity_check` 和行数，再改配置切换到新文件。若准备手工复制文件，必须同时确认旧进程退出且 WAL 已处理，不能只复制活跃数据库主文件。

版本 2 后的每次结构变更应新增一个有序迁移函数、增加升级/失败/保留数据测试、更新本节和版本常量。不得仅修改 `CREATE TABLE IF NOT EXISTS` 后假定运行库已经同步。
